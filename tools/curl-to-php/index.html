Running the generated PHP code

  • Requires ext-curl, which is bundled with almost every PHP distribution. Check with php -m | grep curl.
  • CURLOPT_RETURNTRANSFER is essential. Without it curl_exec() prints the response straight to output and returns true. The generated code always sets it.
  • curl_exec does not fail on 4xx. It returns false only for transport errors. Read CURLINFO_HTTP_CODE — which the snippet does — to detect an HTTP-level failure.
  • File uploads use CURLFile. Passing a raw @/path string has been disabled since PHP 5.6 and will be sent as a literal.
  • Array versus string POST fields. An array makes cURL send multipart/form-data; a pre-encoded string sends application/x-www-form-urlencoded. The generator picks the one matching your command.
  • Prefer Guzzle for anything larger than a script — it gives you retries, middleware and PSR-7 messages.

What gets converted

The parser reads the method, URL and query string, every -H header, cookies and user agent, -u and --oauth2-bearer credentials, all the -d body variants including --data-urlencode and --json, -G, and multipart -F uploads. Flags that only affect the terminal, such as -s or -v, are ignored; flags with no code equivalent are reported above the output rather than dropped silently.
