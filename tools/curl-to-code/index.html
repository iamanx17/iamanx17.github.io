What this tool does

Paste a cURL command — typed by hand, copied from an API's documentation, or taken from your browser's Copy as cURL menu — and get the same request written as runnable code in the language you work in.

The converter parses the command the way a shell would: it handles quoting, backslash line continuations, PowerShell backticks and Windows carets, then reconstructs the request from the flags it finds. The result is a snippet you can paste into a file and run, not a skeleton you have to finish.

How to use it

  1. Pick your target language from the dropdown.
  2. Paste the cURL command into the input box. Output appears as you type.
  3. Read the warnings, if any — they list options that have no equivalent in code.
  4. Press Copy, or use Ctrl/⌘ + Enter to re-run.

Nothing is uploaded. The parser and every generator are plain JavaScript running in your tab, which is why you can safely convert a command that carries a live bearer token.

Examples

A JSON POST with a bearer token

curl 'https://api.example.com/v1/users' \
  -X POST \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer YOUR_TOKEN' \
  -d '{"name":"Ada Lovelace","admin":false}'

Because the body is valid JSON, the converter emits a real object literal — JSON.stringify({ name: "Ada Lovelace", admin: false }) in JavaScript, a dict passed to json= in Python — rather than an opaque string you would have to edit by hand.

A form post with basic auth

curl -u admin:s3cret \
  -d 'grant_type=client_credentials' \
  -d 'scope=read write' \
  https://api.example.com/oauth/token

The two -d flags are joined with & exactly as cURL joins them, the pair is recognised as form-encoded, and -u is converted into the matching Authorization: Basic header with the credentials Base64-encoded.

A file upload

curl -X POST https://api.example.com/v1/files \
  -F 'file=@./report.pdf;type=application/pdf' \
  -F 'visibility=private'

Multipart uploads become a FormData object in JavaScript, files= and data= arguments in Python, a multipart.Writer in Go and a CURLFile in PHP. The boundary is left to the HTTP client, which is why any Content-Type: multipart/form-data header you pasted is dropped — keeping it would produce a malformed request.

Common errors and what they mean

“This does not start with curl”
Only the command itself belongs in the box. Remove a leading shell prompt, a pipe into jq, or the && that joins it to another command.
“Unbalanced single quote”
The paste is truncated, usually because the command wrapped across lines in a chat window. Copy it again, including the closing quote.
“No URL found in the command”
The URL is missing, or it was consumed as the value of a flag. Put the URL first — curl https://… -H '…' — and it will always be found.
Body appears as a string, not an object
The body is not valid JSON. Shell variables such as $TOKEN, single-quoted keys and trailing commas all break parsing. The request is still correct; only the literal is less convenient.
A header you pasted is missing
Headers without a colon are dropped, and a Content-Type naming a multipart boundary is removed on purpose so the HTTP client can generate its own.

When you would use this

  • Turning API documentation into a client. Most API docs show a cURL example. This gets you from that example to working code without transcribing headers by hand.
  • Reproducing a browser request. Copy a request as cURL from DevTools to see exactly which headers your front end sends, then port it to a backend script.
  • Moving a request between languages. Convert once to cURL, then to whatever the receiving service is written in.
  • Debugging an integration. If cURL works but your code does not, generating the code from the same command shows which header or body detail differs.
  • Writing tests and runbooks. A support ticket with a cURL command becomes a reproducible test case in your own stack.

Frequently asked questions

Is the cURL converter free?

Yes. Every tool on curl2code is free, has no account and no usage limit.

Is it safe to paste a command containing an API key?

The converter runs entirely in your browser. The command is parsed by JavaScript on your machine and no part of it — URL, headers or body — is sent to a server. Even so, treat any generated snippet as a secret: it contains the same token you pasted, so do not commit it to a public repository.

Which cURL flags are supported?

Method, URL, headers, cookies, user agent, referer, basic and bearer auth, all the -d/--data variants, --data-urlencode, --json, -G, multipart -F uploads, --compressed, -L and -k. Options with no code equivalent, such as --output or --proxy, are consumed and reported rather than silently dropped.

Why is my body sent as a string instead of an object?

The converter builds a native object literal only when the body is valid JSON. If the JSON has a trailing comma, a single-quoted key or a shell variable in it, it cannot be parsed and is passed through as a raw string instead. Fix the JSON and the output becomes an object.

Can I convert a command copied from Chrome DevTools?

Yes. Right-click a request in the Network tab, choose Copy → Copy as cURL, and paste it in. Browser copies include a long list of headers and cookies; delete the ones your script does not need before using the generated code.

Does the generated code handle errors?

Every snippet checks the response status: fetch and Axios throw on a non-2xx status, Python calls raise_for_status(), Go and Ruby print the status line, and PHP raises on a transport failure. A default timeout is set wherever the client supports one.
